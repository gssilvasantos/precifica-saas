# docs/product

Especificações de funcionalidade — o **quê** e o **porquê**, antes do **como**.

## Convenções

- Um arquivo por funcionalidade: `<slug-da-funcionalidade>.md`.
- Template: `.claude/skills/product-engineering-studio/templates/feature-spec.md`.
- Campo sem resposta é marcado **"a definir"**. Nunca invente propósito, público, número ou
  funcionalidade que não esteja no repositório.
- Suposições vão listadas explicitamente, para serem desmentidas cedo.
- Status no cabeçalho: rascunho · em revisão · aprovada · implementada.

## O que já existe hoje

O histórico funcional do produto está no `README.md` da raiz (organizado por etapa/sprint) e nos
documentos de arquitetura por módulo em `docs/`. Esta pasta é para **specs novas**, escritas
antes da implementação.
